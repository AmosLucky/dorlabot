# PROJECT REQUIREMENTS: DORLA CODE MESSENGER AUTOMATION SAAS

## 1. Project Overview

Build a complete, beautiful, modern, production-oriented SaaS web application for Facebook Messenger chatbot automation using Laravel, PHP, MySQL, Bootstrap 5, HTML, CSS, JavaScript, and the official Meta Graph API and Messenger Platform APIs.

The application will be hosted at:

**Production domain:** https://dorlacode.com/

The platform should allow anybody to register an account, connect their own Facebook Page, configure automated replies, manage Messenger contacts, personalize messages using subscriber names, run eligible messaging broadcasts, and monitor messaging performance.

The platform owner must have a separate super-admin dashboard for managing registered users, connected Facebook Pages, platform activity, system settings, and account status.

Build a real working application, not just a static UI mockup. All buttons, forms, dashboards, navigation items, database operations, authentication flows, and application functions must be implemented and connected properly.

Use a clean, maintainable Laravel architecture with secure tenant isolation. Design the system so additional messaging channels, subscription plans, and integrations can be added later.

## 2. Required Technology Stack

Use the following technologies:

- Backend: Laravel, using the latest stable version compatible with the hosting environment.
- Language: PHP.
- Database: MySQL or MariaDB.
- Frontend: Bootstrap 5.
- Icons: Bootstrap Icons or Font Awesome.
- JavaScript: Vanilla JavaScript and Bootstrap components; use AJAX/fetch where appropriate.
- Templates: Laravel Blade.
- Authentication: Laravel authentication with secure password hashing, login, registration, logout, password reset, and email verification.
- Background processing: Laravel Queues, with Redis where available and a database queue fallback.
- Scheduled jobs: Laravel Scheduler.
- Charts: Chart.js.
- HTTP integration: Laravel HTTP Client.
- Facebook integration: Official Meta Graph API, Messenger Platform Send API, Webhooks, and the appropriate Facebook Login authorization flow.
- Database: Proper migrations, relationships, foreign keys, indexes, seeders, and factories.
- Security: CSRF protection, request validation, authorization policies, rate limiting, encrypted credentials, and secure session handling.

Use Bootstrap 5 throughout the application. Do not use Tailwind CSS as the primary styling framework. Do not use React, Vue, or another frontend framework unless absolutely necessary.

## 9. Messenger Webhooks

GET /webhooks/meta/messenger

POST /webhooks/meta/messenger

The GET endpoint should support Meta's webhook verification handshake.

The POST endpoint must:

- Verify the X-Hub-Signature-256 header using the Meta app secret and the raw request body.
- Reject invalid signatures.
- Parse incoming webhook payloads safely.
- Identify the relevant connected Page.
- Identify the appropriate tenant using the connected Page record.
- Handle incoming messages.
- Handle postbacks and button interactions.
- Handle message delivery and read receipts where supported.
- Handle supported comment events.
- Queue appropriate processing jobs.
- Respond promptly to Meta.
- Avoid processing duplicate webhook events.
- Log errors without logging access tokens, app secrets, or unnecessary personal data.

Implement webhook event processing in dedicated service classes and queue jobs rather than putting all business logic in controllers.

Add idempotency protection for duplicate messages, events, and comments.
